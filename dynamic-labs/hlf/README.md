# Hyperledger Fabric Lab

A managed Hyperledger Fabric classroom lab for the dynamic-labs framework.
Runs a real 4-org permissioned consortium shared by 20 students by default,
with support for up to 40 on larger hosts — each with their own on-demand
peer and shell, all writing to the same channel.

- Routed under `/labs/hlf/`
- Managed by [`lab-manager.sh`](../lab-manager.sh)
- One shared consortium ledger; per-student peers spun up on demand
- Instructor auth lives at top-level `/instructor` (one login covers every
  lab's instructor surface)
- Offline-clean: all browser assets vendored into the image at build time

## Topology

```
                          ┌────────────────────┐
                          │     orderer.*      │  ── channel: diplomas
                          └─────────┬──────────┘
                                    │
    ┌───────────────┬──────────────┼──────────────┬───────────────┐
    ▼               ▼              ▼              ▼               ▼
 peer0.cascadia  peer0.chesapeakecanoe  peer0.southhudson peer0.mapleleaf  [s01…sNN]
 (Cascadia      (Chesapeake Canoe       (South Hudson    (Maple Leaf     on-demand
  State Univ.)   Industries)     Institute)       Academy)       student peers
        └──────────────┬────────────────┬──────────────┘              │
                       │                │                             │
                       └────── 3-of-4 MAJORITY endorsement ───────────┘
```

Fixed services (always on when the lab is up):

- `hlf` — static frontend (lesson, explorer, instructor console, etc.)
- `hlf-runner` — Flask control plane. Owns the lane manager, claim
  manager, scenario engine, and every chain helper. By default it also
  auto-starts the managed Fabric network on container boot and tears the
  network down on container exit. Shared instructor auth is now owned by
  the dedicated top-level instructor auth service.
- Fabric: 1 orderer + 4 org peers (Cascadia State, Chesapeake Canoe University,
  South Hudson, Maple Leaf) + Meridian (Org5, read-only) + chaincode
  (asset-transfer-basic fork). Each peer/orderer container runs a
  built-in ttyd instance (baked into `hlf-peer-ttyd` / `hlf-orderer-ttyd`
  images via `Dockerfile.ttyd`).

On-demand services (spun up by the lane manager):

- `peer0.studentNN.example.com` — one per active student, joined to the
  shared channel. Brought up when the student claims a station, stopped
  when they go idle (see `HLF_LANE_IDLE_TIMEOUT`).

## Routes

```
/labs/hlf/                           Student lesson home (Chapter nav + TOC)
/labs/hlf/claim                      Claim a station → redirects to /c/<uuid>/
/labs/hlf/c/<uuid>/                  Per-student lesson surface (session cookie)
/labs/hlf/s/<sid>/                   Per-lane views (explorer, ttyd, etc.)
/labs/hlf/explorer/                  Unified block/network/state inspector
/labs/hlf/explorer/governance/       Channel policy drilldown
/labs/hlf/explorer/chaincode/        Chaincode detail + source
/labs/hlf/peer/<org>/                Node detail for consortium peers
/labs/hlf/peer/<org>/console/        [instructor-gated] ttyd into consortium peer
/labs/hlf/orderer/console/           [instructor-gated] ttyd into orderer
/labs/hlf/hlf_instructor.html        [instructor-gated] Instructor console
/instructor/                         Top-level instructor login portal
/instructor/term/<org>/              [instructor-gated] consortium peer ttyd
/api/instructor/{login,logout,verify,whoami}
/labs/hlf/api/hlf/...                Control-plane API (status, lanes, claims,
                                     exercises, explorer, fault, seed, …)
```

The routing is stitched together by the shared outer router at
[`../router/routes.conf`](../router/routes.conf) + the lab-specific
[`router/routes/hlf.conf`](../router/routes/hlf.conf) and
[`router/routes/hlf-lanes.conf`](../router/routes/hlf-lanes.conf) (the
latter is generated by the lane manager for per-student routing).

## Managed Flow

From `dynamic-labs/`, bring up the shared router first:

```bash
./lab-manager.sh deploy --mode student --no-tls
```

Then start the HLF lab:

```bash
./lab-manager.sh start hlf
```

Check status:

```bash
./lab-manager.sh status hlf
docker compose -f hlf/docker-compose.yml ps
```

Stop:

```bash
./lab-manager.sh stop hlf
```

## Instructor flow

1. Open `/instructor/` and log in with the centralized instructor
   credentials from `./.runtime/instructor-credentials.txt`.
   New deployments should set `INSTRUCTOR_AUTH_USER` and
   `INSTRUCTOR_AUTH_KEY` on the dedicated instructor auth service.
   `HLF_INSTRUCTOR_USER` and `HLF_INSTRUCTOR_KEY` remain only as
   compatibility fallbacks.
2. From the portal, open **HLF — Instructor Console**.
3. By default the Fabric network starts automatically when `hlf-runner`
   boots. **Start Network** remains available as a manual retry/recovery
   action and does _not_ start any student peers.
4. Set the hot-swap **Pool Size** (recommend ~20% of class size) and
   distribute `/labs/hlf/claim` to students.
5. Watch the lane grid during class. Per-lane Start/Stop/Reset and
   per-claim Release are in the Classroom panel. Class-wide fault demos
   are in Scenario Controls. End-of-class reset is **Reset Network**.

Full runbook: [`docs/CLASSROOM_OPERATIONS.md`](docs/CLASSROOM_OPERATIONS.md).

## Student flow

Each student hits `/labs/hlf/claim` once. The claim manager assigns the
lowest free lane (`s01`…`sNN`, based on `HLF_STUDENT_COUNT`), sets an `hlf_session` cookie, and
redirects to `/labs/hlf/c/<uuid>/`. The lane manager brings the student's
peer up in the background (hot peers from the pool serve instantly). Each
student gets:

- Their own **org** and **peer** on the shared channel
- Their own **ttyd shell** scoped to their admin MSP (no cross-access)
- A **per-student exercise surface** at `/labs/hlf/s/<sid>/…`
- Reads/writes that hit the **same ledger** as everyone else — classmate
  transactions show up in their explorer and vice versa

Per-student `Reset` wipes that student's peer only; the shared ledger
keeps going. `Reset Network` (instructor only) regenerates everything
from genesis.

## Local smoke test

```bash
docker network create router-net || true
cd ../router && HTTP_PORT=8081 TLS_PORT=8443 NGINX_CONF=nginx-http.conf docker compose up -d router
cd ../hlf && docker compose up -d --build
curl -I http://127.0.0.1:8081/labs/hlf/
curl http://127.0.0.1:8081/labs/hlf/api/hlf/status
python3 scripts/smoke_test_routes.py
```

Route ownership:

- `/labs/hlf/` (static UI) → `hlf`
- `/labs/hlf/api/hlf/*` → `hlf-runner`
- `/labs/hlf/s/<id>/*` and per-student ttyd → `hlf-runner` (lane manager
  routes directly to per-peer ttyd)
- `/instructor/*` and `/api/instructor/*` → `instructor-auth-service`

## Offline runtime

The HLF image downloads pinned browser assets during `docker build` and
stores them under `web_ui/vendor/` in the image, so runtime browser
access never hits third-party CDNs. Fabric CA material + peer/orderer
compose files are rendered from repo-owned templates under
[`managed_runtime/`](managed_runtime).

## Environment variables

| Var | Default | Purpose |
| --- | --- | --- |
| `INSTRUCTOR_AUTH_USER` | `instructor` | Central instructor login username |
| `INSTRUCTOR_AUTH_KEY` | generated at deploy | Central instructor login password |
| `HLF_INSTRUCTOR_USER` | unset | Legacy compatibility fallback username for the auth service |
| `HLF_INSTRUCTOR_KEY` | unset | Legacy compatibility fallback password for the auth service |
| `HLF_STUDENT_COUNT` | `20` | Number of provisioned student lanes, up to the platform limit of 40 |
| `HLF_LANE_IDLE_TIMEOUT` | `1200` | Seconds of inactivity before a student peer is stopped |
| `HLF_LANE_SWEEP_INTERVAL` | `60` | How often the idle sweeper runs |
| `HLF_AUTO_START_NETWORK` | `1` | Auto-run `./lab.sh up` when `hlf-runner` starts |
| `HLF_STOP_NETWORK_ON_EXIT` | `1` | Run `./lab.sh down` when `hlf-runner` stops |
