## Opening Exercise: Find the Faulty Node

**Scenario:** You are all servers in a decentralized network. You just received a critical system update. However, one of you has been hacked and corrupted with a **Byzantine Fault**.

**The Rules:**

1.  **The Payload:** 6 of you will receive the exact same "System State" (a secret word or phrase). 1 of you will receive a blank state: *You are the Compromised Node*.
2.  **The Broadcast:** Go around the circle. Each node must say exactly **one word** related to the secret payload to prove to the network that you possess the true state.
    *   *Strategy:* Be specific enough to prove you are a loyal node, but vague enough that the Compromised Node can't guess the payload!
3.  **Consensus:** On the count of three, point at the node you believe is compromised. 
4.  **Resolution:** If the network votes out the Compromised Node, the network is safe! If the network votes out a loyal node, or if the Compromised Node can accurately guess the payload, the network crashes!

::: {.notes}
Time: ~10 min

**Instructor Notes and Script:**

This exercise is an adaptation of social deduction games like "Copycat" or "Chameleon." It is a fantastic, high-energy way to introduce the concepts of distributed systems, mutual suspicion, and Byzantine faults before you even define them.

**Preparation:**
Have a set of index cards ready, or use a tool like https://copycat.subaverage.site/ if students have devices. 
If using physical cards for a group of 7 volunteers:
- Write a specific phrase on 6 cards (e.g., "Nuclear Launch Codes", "Bitcoin", "Ransomware", "The Pentagon"). 
- On the 7th card, write: "You are the Compromised Node. You have no data. Blend in and guess the data."

**Execution:**
1. Call up 5-8 volunteers to the front of the room, or do this in small table groups if manageable.
2. Hand out the cards face down. Tell them to look at their state but keep it hidden.
3. Pick a random student to start. They say one word. (e.g., if the word is "Bitcoin", they might say "Digital"). 
4. The next person goes (e.g., "Money"). The Compromised Node has to quickly adapt and say something that fits the pattern (e.g., "Wallet") without knowing the actual word.
5. Once everyone has gone, ask the network to vote. Count to three, and have everyone point at who they think the hacker is. 
6. Ask the voted-out person to reveal their card. If it's the Compromised Node, ask them if they can guess the actual word to steal the win.

**Debrief & Script:**
"Alright, let's look at what just happened. In this game, there was no 'central server' or 'instructor' telling you who was right or wrong. You were a **distributed network**. 

To figure out what the truth was, you had to rely entirely on peer-to-peer communication. But you had a major problem: you couldn't fully trust the other nodes. You had to operate under **mutual suspicion**. 

The compromised node in our game represents what computer scientists call a **Byzantine Fault**—a piece of the network that isn't just broken and silent, but is actively participating, lying, and trying to trick the honest nodes into making a bad decision. In a centralized system, a firewall or an admin would just kick them out. In a decentralized system, the honest nodes have to use cryptography and consensus algorithms to figure out who the liar is and achieve consensus safely. That exact challenge is the foundation of blockchain technology, and it's what we are going to explore today."

:::

This is a brilliant idea. Relying on an external dependency for a live classroom exercise is risky, and building it internally gives you total control over the theme (you can use blockchain-specific words) and the flow.

Recommendations for Game Size
For this type of social deduction game, 5 to 8 players is the sweet spot.

Fewer than 5: The Insider has too few people to blend in with, and voting is too obvious.
More than 8: The round takes too long, and it becomes too easy for the Insider to guess the word based on 7 other clues.
Recommendation: We will design the lobby to group students into "Rooms" of up to 6 players. If a 7th student joins, they seed a new room.
System Architecture
To make this real-time and low-friction, we will use:

Flask + Flask-SocketIO: For instant updates without requiring students to refresh their browsers.
Vanilla JS + HTML/CSS: A single-page template that updates its state (Lobby -> Playing -> Voting -> Results) based on WebSocket events.
Docker + Gunicorn/Eventlet: To easily deploy behind your Nginx reverse proxy.

import random
import string
from flask import Flask, render_template, request
from flask_socketio import SocketIO, emit, join_room, leave_room

app = Flask(__name__)
app.config['SECRET_KEY'] = 'blockchain-course-secret'
# cors_allowed_origins="*" is important when running behind a reverse proxy
socketio = SocketIO(app, async_mode='eventlet', cors_allowed_origins="*")

ROOM_MAX_SIZE = 6

SECRET_WORDS = [
    "Cryptography", "Blockchain", "Bitcoin", "Ransomware", 
    "Ledger", "Satoshi", "Ethereum", "Smart Contract", 
    "Mining", "Wallet", "Node", "Consensus"
]

# In-memory state (suitable for a single container classroom app)
# Structure: { room_id: { 'players': {sid: name}, 'state': 'lobby|playing|voting|results', 'insider': sid, 'word': str, 'votes': {voter_sid: target_sid} } }
rooms = {}
player_to_room = {}

def get_or_create_room():
    """Find an available room or create a new one."""
    for room_id, data in rooms.items():
        if len(data['players']) < ROOM_MAX_SIZE and data['state'] == 'lobby':
            return room_id
    
    # Create new room
    room_id = ''.join(random.choices(string.ascii_uppercase + string.digits, k=4))
    rooms[room_id] = {
        'players': {},
        'state': 'lobby',
        'insider': None,
        'word': None,
        'votes': {}
    }
    return room_id

def broadcast_room_state(room_id):
    room = rooms.get(room_id)
    if room:
        players_list = [{'id': sid, 'name': name} for sid, name in room['players'].items()]
        socketio.emit('room_update', {'room_id': room_id, 'players': players_list, 'state': room['state']}, to=room_id)

@app.route('/')
def index():
    return render_template('index.html')

@socketio.on('join')
def handle_join(data):
    name = data.get('name', 'Anonymous')
    room_id = get_or_create_room()
    
    join_room(room_id)
    rooms[room_id]['players'][request.sid] = name
    player_to_room[request.sid] = room_id
    
    emit('joined', {'room_id': room_id, 'name': name})
    broadcast_room_state(room_id)

@socketio.on('start_game')
def handle_start():
    room_id = player_to_room.get(request.sid)
    room = rooms.get(room_id)
    
    if room and room['state'] == 'lobby' and len(room['players']) >= 3:
        room['state'] = 'playing'
        room['word'] = random.choice(SECRET_WORDS)
        room['insider'] = random.choice(list(room['players'].keys()))
        room['votes'] = {}
        
        # Notify each player of their role privately
        for sid in room['players'].keys():
            if sid == room['insider']:
                emit('role_assigned', {'role': 'insider', 'word': None}, to=sid)
            else:
                emit('role_assigned', {'role': 'loyal', 'word': room['word']}, to=sid)
                
        broadcast_room_state(room_id)

@socketio.on('trigger_voting')
def handle_trigger_voting():
    room_id = player_to_room.get(request.sid)
    room = rooms.get(room_id)
    if room and room['state'] == 'playing':
        room['state'] = 'voting'
        broadcast_room_state(room_id)

@socketio.on('submit_vote')
def handle_vote(data):
    target_sid = data.get('target_sid')
    room_id = player_to_room.get(request.sid)
    room = rooms.get(room_id)
    
    if room and room['state'] == 'voting':
        room['votes'][request.sid] = target_sid
        # If everyone has voted, move to results
        if len(room['votes']) == len(room['players']):
            room['state'] = 'results'
            
            # Tally votes (simplified for classroom, can be discussed by instructor)
            results = {
                'insider_id': room['insider'],
                'insider_name': room['players'][room['insider']],
                'word': room['word']
            }
            socketio.emit('game_over', results, to=room_id)
            broadcast_room_state(room_id)

Nginx Reverse Proxy Configuration
Because this app uses WebSockets via Flask-SocketIO, your Nginx reverse proxy needs specific headers to allow the connection to upgrade from HTTP to WS. If these are missing, Socket.IO will fall back to HTTP long-polling (which works, but is slower).

Here is the block you will want to include in your Nginx configuration (e.g. nginx.conf or your sites-enabled file):

nginx
server {
    listen 80;
    server_name your-domain-or-ip.com;

    location / {
        proxy_pass http://localhost:5000; # Assuming container port 5000 is mapped to host 5000
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "Upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
